five core pillars

1. Task Pairs & Cross-Vendor Execution Pool (Pair)
Executor × Auditor · PASS / REWORK

A flagship Brain decomposes goals into dependent Briefs and numbered checklists, then dispatches isolated Executor + Auditor pairs from your cross-vendor Execution Pool—covering single-model blind spots while spreading usage across providers and switching within your pool when rate limits occur.

  • Mix flagship and secondary tiers across Claude Code, Codex, Antigravity CLI, Qwen, and more.
  • Native Split View (Executor × Auditor) with real-time checklist tracking and structured PASS / REWORK convergence.
  • Global Task Mode orchestrates multi-phase pipelines across servers and worktrees without vendor lock-in.
2. Controlled Nodes & AI Computer Use (OCU)
^^(nodeId) · Behind NAT

Turn Linux, Windows, and macOS machines behind NAT into AI-operated nodes—no public IP, no VPN, no port forwarding.

  • Scoped exec_remote shell execution, direct/relay file transfers, and independent per-node credentials.
  • Typed GUI and CDP browser automation via computer_use_call and Open Computer Use.
3. Built-in 4K Remote Desktop
4K · 4-Tile Wall · Human Control

Built directly into IM.codes with no separate remote-desktop add-on fees under your IM.codes license—open live remote desktops from any browser or phone across Windows, macOS, and Linux.

  • 4-tile multi-host Desktop Wall to monitor multiple computers at once.
  • Touch navigation and virtual mouse on mobile; human stays in ultimate control anytime.
4. Cloud Docs & Collaborative Editing
ONLYOFFICE · DocBuilder · & Picker

Built-in Cloud Docs powered by ONLYOFFICE and DocBuilder—keep team specs, runbooks, and AI Skills alongside your code.

  • Inject any Cloud Doc directly into an agent prompt with the & picker or cloud_docs MCP tool.
  • Create, convert, edit, and share DOCX/XLSX/PPTX/Markdown documents collaboratively.
5. Team Sharing & Access Control
Viewer / Participant · Revocable

Share Controlled Nodes, live sessions/sub-sessions, and Cloud Docs per user or group with instant permission downgrade or revocation.

  • Role-based access: viewer for read-only review, participant to send prompts or operate covered nodes.
  • Private groups isolate personal and family machines cleanly from team workspaces.

why

When you leave your desk, most coding-agent workflows fall apart. Even at your desk, single-model runs get stuck in blind spots, vendor tools lock your history in proprietary clouds, and coordinating work across multiple machines means juggling SSH, VNC, and scattered docs. IM.codes solves all three in one self-hosted, zero-lock-in workbench: cross-vendor Task Pairs review each other before code lands, Controlled Nodes + 4K Remote Desktop put every machine under AI and human command, and Shared Memory + Cloud Docs stay permanently yours.

shared agent context

IM.codes keeps a searchable memory of solved work — structured problem→solution summaries instead of raw prompt logs. Relevant history is recalled automatically for new prompts and session startup, and every injection stays visible in the timeline.

  • Personal memory stays local by default, with optional cloud sync for processed summaries across your devices.
  • Enterprise shared context lets teams reuse fixes across workspaces and projects with queryable memory, stats, and inspection UI. It is still under active development and has not been fully production-tested yet.
  • Multilingual recall uses local embeddings plus pgvector-backed server search, so related fixes can be found across different languages.
  • Timeline cards show exactly what was injected, with relevance score, recall count, and last-used metadata.

managed MCP tools

Supported SDK-backed agents receive a daemon-managed stdio MCP server with one runtime-scoped surface for memory, Task Pairs, Cloud Docs, Computer Use, agent messaging, and scheduled follow-ups, without raw auth tokens or ad hoc shell commands.

  • search_memory & get_memory_sources recall prior decisions, bugs, and provenance snippets across providers.
  • pair_create, pair_verdict, pair_close, and execution_pool_set orchestrate isolated Executor × Auditor workflows.
  • exec_remote, send_file_to_machine, fetch_file_from_machine, and computer_use_call operate Controlled Nodes safely.
  • cloud_docs manages collaborative Cloud Docs, ONLYOFFICE edits, and DocBuilder conversions; save_observation & save_preference persist durable knowledge.
  • send_list_targets, send_im_message, and cron_* coordinate sibling sessions and scheduled follow-ups.
  • Runtime-bound identity prevents forged namespace, user, server, token, or routing fields; provider-level ready/degraded status and redacted recent calls stay visible in the UI.

OpenSpec Auto Deliver

Turn an OpenSpec change folder into a supervised delivery run: proposal/spec audit, implementation, validation hints, Team audit/rework, automatic scoring, and a visible final handoff.

spectasksimplementationtestsrisk
  • One-click launch resolves the owning session, reads tasks.md, locks the Team lane, and keeps live progress in the UI.
  • Spec audit can run before implementation through the normal Team flow, using authoritative JSON instead of trusting chat summaries.
  • Implementation prompts stay focused on the selected OpenSpec change and surface safe validation command candidates from project manifests.
  • Automatic module scoring rates spec, tasks, implementation, tests, and risk with evidence visible in run details.
  • Fail-closed gates ask for human input on bad audit output, exhausted limits, manual interference, or unreadable tasks. Auto Deliver never stages, commits, or pushes code.

supervised execution

IM.codes can supervise supported transport sessions turn by turn instead of relying on blind auto-continue. Auto checks whether the latest turn is done, should continue, or should return control to you.

  • Per-session Auto modes: Off, Supervised, and Supervised + audit.
  • At the idle boundary, Auto can classify a turn as complete, continue, or ask_human, then dispatch the next continue prompt in the same session.
  • Supervised + audit can run an audit→rework loop before handing control back, so finished work is reviewed instead of trusted blindly.
  • Global defaults seed new sessions. Set a default supervisor backend, model, and timeout once — each session snapshots them at enable time and can still override backend/model/timeout and audit mode individually.
  • Two-layer custom supervision instructions. Keep a global supervision persona plus a per-session addition — by default the two are concatenated into the prompt, or tick the session's “Override global” checkbox to ignore the global value for that session.

architecture

You (browser / desktop / mobile / iPhone Duo / Watch) │ WebSocket · WebRTC 4K Remote Desktop Server (self-hosted, relays connections, Cloud Docs & pgvector memory) │ WebSocket Daemon & Controlled Nodes (your machines behind NAT) │ tmux / ConPTY / SDKs / managed MCP / OCU AI Force (Claude Code · Codex · Antigravity CLI · OpenClaw · Qwen)

The daemon runs on your dev machines and Controlled Nodes behind NAT, managing process-backed sessions through tmux/ConPTY plus transport-backed sessions through SDKs and network protocols. It owns the managed MCP server for runtime-scoped memory, Task Pairs, Cloud Docs, OCU, Send, and Cron tools. Your self-hosted server relays sessions, Cloud Docs, and 4K Remote Desktop streams—everything stays under your control with zero vendor lock-in.

openclaw connect

If OpenClaw is running on the same machine as the daemon, connect IM.codes to the local OpenClaw gateway with:

imcodes connect openclaw
  • Default gateway URL: ws://127.0.0.1:18789
  • Token auto-detected from ~/.openclaw/openclaw.json, or pass --token / OPENCLAW_GATEWAY_TOKEN
  • OpenClaw sessions and child sessions sync into IM.codes automatically
  • Saved to ~/.imcodes/openclaw.json so the daemon can reconnect automatically
  • Use imcodes disconnect openclaw to remove the saved config
imcodes connect openclaw --url wss://gateway.example.com OPENCLAW_GATEWAY_TOKEN=... imcodes connect openclaw

Only tested on macOS so far. Remote plain-text ws:// URLs require --insecure.

self-host

Deploy server + daemon on a single machine. Requires Docker and a domain with DNS pointing to the server.

curl -fsSL https://im.codes/install.sh | bash # fallback: npm install -g imcodes mkdir imcodes && cd imcodes imcodes setup --domain imc.example.com

Generates all config, starts PostgreSQL + server + Caddy with automatic HTTPS, creates admin account, and binds the local daemon. Credentials printed at the end.

To connect additional machines:

curl -fsSL https://im.codes/install.sh | bash # Windows: irm https://im.codes/install.ps1 | iex · fallback: npm install -g imcodes imcodes bind https://imc.example.com/bind/<api-key>

Manual setup:

git clone https://github.com/im4codes/imcodes.git && cd imcodes ./gen-env.sh imc.example.com # generates .env, prints admin password docker compose up -d

Generated docker-compose.yml uses pgvector/pgvector:pg18 for PostgreSQL.
